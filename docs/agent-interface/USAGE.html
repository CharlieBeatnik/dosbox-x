● Live debug channel

Drive DOSBox-X like a program, not a person.

A loopback TCP socket on the running emulator, speaking newline-delimited JSON. Pause the CPU, type into a DOS guest, read and write registers and memory, set typed breakpoints, watch every control transfer, snapshot the whole machine, and react to events — all from your own client, in any language.

This is the consumer-facing guide. If you are an automated agent — or a human writing one — read it end to end before opening any source. For the design rationale see PLAN.md; for build & verification see SMOKE.md; for development history see HANDOVER.md.

newline-delimited JSON loopback only debug build stdlib Python client
python — drive the guest
from dbxagent import DbxAgent   # contrib/agent-client/dbxagent.py

with DbxAgent(portfile="dbxport.txt") as a:
    print(a.vm_version())        # {'version':'2026.05.02', ...}
    a.keyboard_type("DIR\r")     # type into the DOS guest
    a.cpu_pause()
    regs = a.call("regs.get")    # structured CPU snapshot
    print(f"CS:EIP = {regs['cs']:04x}:{regs['eip']:08x}")
    a.cpu_run()

01 Capabilities at a glance #

Ten capability buckets, each backed by typed commands. Hover a card.

⏯️

Execution control

Pause & resume the CPU headlessly, or single-step into and over calls with structured per-step register + disassembly output.

🧮

Registers

Read every GPR, segment register, EIP and EFLAGS in one reply (regs.get), or write named registers (regs.set).

💾

Memory

Read or write up to 64 KB at a time by seg:off, linear or physical address — base64 on the wire.

🛑

Breakpoints

Typed execution & interrupt breakpoints with stable handles, plus conditional / Nth-hit BPs with atomic on-hit capture macros.

🎯

Transfer watches

Catch the instruction behind a FAR / NEAR / interrupt transfer to a target, or every entry into a code region.

🔭

Observability

Non-halting probes, an instruction trace ring, structured disassembly, and a full typed status snapshot — every observer is provable.

📸

Screen capture

Trigger the native screenshot path and get back the PNG's absolute path — raw VGA scanlines or the cooked render output.

⌨️

Keyboard

Type ASCII into the guest, or drive raw key make/break events by name for modifiers and special keys.

⏱️

State snapshots

Save the whole machine to a slot and restore it instantly — byte-identical, deterministic investigate-fix-retry loops.

📡

Events & logs

Subscribe to log lines and to bp.hit, state.paused, transfer and memory-write events — react asynchronously.

What is not available

Anything the curses debugger draws into a pane — the register pane, the disassembly pane, the hex/ASCII data pane — is invisible to the agent (use regs.get / mem.read / cpu.disasm instead). MEMDUMP writes a file on disk rather than returning bytes inline. Mouse input is still planned for Phase 2. See Not capturable for the full list.

02 Requirements #

  • DOSBox-X debug build. The agent is gated on C_DEBUG; the release build is byte-identical to upstream — no listener, no port file. On Windows: VS solution vs/dosbox-x.sln, configuration Debug | x64, toolset v143. On Linux/macOS: ./build-debug. A few commands additionally need a heavy-debug build.
  • A way to launch DOSBox-X with CLI flags.
  • A TCP client. The reference is contrib/agent-client/dbxagent.py — Python 3.8+, stdlib only.
ℹ️

Badge legend. paused only needs cpu.pause first · heavy-debug needs a heavy-debug build · emits event pushes async events · deferred reply reply arrives later · Phase 2 not yet implemented.

03 Quickstart #

1 · Launch DOSBox-X with the agent listening

dosbox-x -agent-listen 127.0.0.1:0 -agent-portfile dbxport.txt -fastlaunch
  • -agent-listen 127.0.0.1:0 — bind to loopback, OS-assigned ephemeral port.
  • -agent-portfile dbxport.txt — DOSBox-X writes the chosen port number to this file as soon as the listener is up. Poll for the file's existence; don't connect before it appears.
  • -fastlaunch — skip the splash for faster iteration (optional).
  • -agent-token <hex> — parsed but not enforced. Don't rely on it for security; loopback-only binding is the real gate.

Equivalent without CLI flags — in dosbox-x.conf:

[agent]
enabled  = true
listen   = 127.0.0.1:0
portfile = dbxport.txt

2 · Connect from Python

from dbxagent import DbxAgent          # contrib/agent-client/dbxagent.py

with DbxAgent(portfile="dbxport.txt") as a:
    print(a.vm_version())                       # {'version':'2026.05.02','machine':'vga','build':'heavy-debug'}
    a.keyboard_type("DIR\r")
    a.cpu_pause()
    regs = a.call("regs.get")                   # {'eax': 0, 'ebx': 0, ... 'eflags': 0x246}
    print(f"CS:EIP = {regs['cs']:04x}:{regs['eip']:08x}")
    print(a.debugger_command("BPLIST")["output"])
    a.cpu_run()

That's the whole loop: connect, issue commands synchronously, drain events asynchronously, close.

04 Wire protocol #

One JSON object per line. UTF-8. \n-terminated. No framing prelude, no length prefix, no handshake.

→

Request

{"id": N, "cmd": "...", "args": {...}}

id — any number; echoed on the matching reply (use a monotonic integer). args is optional, omitted for commands that take none.

←

Reply

Same id, plus either
{"ok": true, "result": {...}} or
{"ok": false, "error": {"code","message"}}.

⚡

Event

Server-initiated: {"event": "...", ...}. No id. Demultiplex by checking for "id" — replies have one, events don't.

💡

The reference client demultiplexes in a single reader thread: messages with an id resolve the matching pending call; everything else lands on the event queue.

06 Registers & VM #

vm.version #

no args
★
Ability: a cheap connection sanity-check — confirms the channel is live and tells you what you're driving.

version is a string like "2026.05.02". machine is the lowercased [machine] enum (hercules, cga, tandy, pcjr, ega, vga, amstrad, pc98, fmtowns, mcga, mda, unknown). build is "debug" or "heavy-debug" ("release" is unreachable — the agent is compiled out).

{"version": "2026.05.02", "machine": "vga", "build": "heavy-debug"}

regs.get #

no argsrunning or paused
★
Ability: read the entire CPU state — all GPRs, segment registers, EIP and EFLAGS — in one structured reply. The supported replacement for the R / R EAX commands (there is no R handler, and the curses register pane is invisible to the agent).
{
  "eax": 4275878552, "ebx": 0, "ecx": 0, "edx": 0,
  "esi": 0, "edi": 0, "ebp": 0, "esp": 65520,
  "eip": 256,
  "cs": 4096, "ds": 4096, "es": 4096,
  "fs": 0, "gs": 0, "ss": 4096,
  "eflags": 582
}

All values are unsigned JSON numbers — 32-bit for GPRs and EIP, 16-bit for segment registers. Print hex with f"{regs['cs']:04x}". Prefer this over the legacy EV <register> reader, which returns only one register per call.

regs.set #

paused only
★
Ability: write one or more registers — the write counterpart to regs.get. The agent applies the write between instructions (a safe point), so the CPU must be paused first.
{"id": 1, "cmd": "regs.set", "args": {"eax": 4275878552, "cs": "0x0824"}}
  • Names: eax..esp, eip (32-bit); cs/ds/es/fs/gs/ss (16-bit); eflags. Values are JSON numbers or hex strings.
  • All-or-nothing: an unknown name, a non-numeric value, or a segment above 0xFFFF rejects the whole request with bad_args and writes nothing.
  • Segment writes use the real-mode form (value + real-mode base; protected-mode descriptor limits are not reloaded — same as the curses SR command). eflags goes through CPU_SetFlags, so reserved/masked bits are handled.

Reply {"set": ["cs","eax"], "regs": {…}} echoes the names applied plus a full post-set snapshot, so you confirm the write with no follow-up call.

a.cpu_pause()
a.regs_set(eax=0xDEADBEEF, eip=0x100)        # keyword args or a dict

07 Memory #

mem.read #

running or paused≤ 64 KB
★
Ability: read up to 64 KB of guest memory at a time, base64-encoded. The supported replacement for MEMDUMP (which writes a file) and the curses D/DV/DP data panes (invisible to the agent).
{"id": 1, "cmd": "mem.read",
 "args": {"kind": "seg:off", "addr": "1000:0100", "len": 256}}
  • kind — "seg:off" (real-mode "SEG:OFF" hex, linear = seg<<4 + off, read through paging), "linear" (paged/virtual, through the TLB), or "physical" (bypasses paging; reads past end-of-memory return 0xFF).
  • addr — hex, with or without 0x.
  • len — 0 to 65536. Chunk larger reads.

Reply {"bytes": "<base64>", "len": N}.

import base64
res = a.call("mem.read", kind="seg:off", addr="0040:0017", len=2)
keyboard_flags = base64.b64decode(res["bytes"])  # BIOS data area

mem.write #

race-free≤ 64 KB
★
Ability: write raw bytes into guest memory — the store counterpart to mem.read. Same kind/addr semantics; the bytes arrive base64-encoded.
{"id": 1, "cmd": "mem.write",
 "args": {"kind": "seg:off", "addr": "1000:0100", "bytes": "kJDNIQ=="}}

Reply {"written": N}. Does not require the CPU paused — the agent applies the store between instructions — but a running guest may immediately overwrite it, so pause first when patching a value the guest is actively using.

a.mem_write("seg:off", "1000:0100", b"\x90\x90\xcd\x21")   # raw bytes; encoded for you

mem.watch #

mem.writeheavy for CS:IP
★
Ability: a true write-intercept that fires at the instant of the store and names the storing instruction's CS:IP — the decisive "which instruction stamps this value?" measurement, in one run. Unlike BPM (a per-instruction value-change poll) there is no change-detection or next-instruction-boundary skew.
{"id": 1, "cmd": "mem.watch", "args": {"seg": "0824", "lo": "6000", "hi": "6FFF",
   "size": 2, "when": {"new_eq": "0853"}}}
   → {"armed": true, "seg": 2084, "lo": 24576, "hi": 28671, "size": 2,
      "predicate": "new_eq=0x853"}

Each matching write emits a mem.write event:

{"event": "mem.write", "seg": 2084, "off": 27164, "addr": "0824:6A1C", "size": 2,
 "old": 1889, "new": 2131,
 "from_cs": 2084, "from_ip": 4718, "from": "0824:126E",
 "from_text": "mov word [6a1c],0853"}
  • from_cs:from_ip (and from) — the instruction that performed the store. from_text is its disassembly (heavy-debug only).
  • old / new — pre/post values at the access width. old is null for the VGA framebuffer & MMIO (reading them back has side effects — the plane latches).
  • size filters to 1/2/4-byte writes; omit to match any width. The range [lo, hi] is matched against the write's starting offset.
  • when — a value predicate so the one write you care about isn't buried under thousands: {"new_eq": V}, {"new_ne_old": true}, {"new_and_mask_eq": {"mask","value"}}, or {"becomes_eq": V}.
💡

becomes_eq — value-landed. Fires once per rising edge when the value_size-byte unit at seg:lo becomes V, by any overlapping store (byte-wise, partial, rep movs, a block copy starting below lo). Answers "when does this location reach V?" rather than "which store wrote V?" — the right tool when a field is populated a byte at a time, where new_eq would report a false zero.

Covers normal RAM and the VGA framebuffer (A0000–BFFFF). The hit counter surfaces in debug.status under watches.mem, so a watch that fired (or never did) is provable without consuming the event stream. Single sentinel — calling again replaces it.

08 Execution control #

cpu.pause / cpu.run #

state.paused / state.running
★
Ability: halt and resume the CPU headlessly — cpu.pause flips into the debugger loop with no curses window. Both reply immediately with {}; watch the state.paused / state.running events for the actual transition.

regs.get and mem.read are safe whether running or paused (they snapshot in place). Inspection debugger.commands (BPLIST, EV, IDT, …) are safe anytime; commands that mutate loop state (RUN, step) should be issued only while paused.

cpu.step / cpu.step_over #

paused only
★
Ability: walk a suspect dispatch one instruction at a time and see where control goes — the precise, deterministic alternative to arming a watch and hoping it fires. Returns structured output the curses T/P keys can't.
{"id": 1, "cmd": "cpu.step"}
  → {"regs": {"eax": 43690, "ebx": 48059, … , "eflags": 518},
     "cs_ip": "0814:0000017D",
     "insn": {"cs_ip": "0814:017D", "bytes": "BB BB BB", "text": "mov bx,0xbbbb"}}
  • regs — full post-step snapshot (the regs.get shape): the "where did the value go?" answer after the instruction retired.
  • cs_ip — the new CS:EIP (where the CPU is now).
  • insn — disassembly of the instruction now at CS:IP (the one about to execute).

cpu.step is trace-into: exactly one instruction; stepping a CALL/INT descends into the target. cpu.step_over is step-over: a CALL/INT/LOOP/REP is treated as one unit (a temporary BP at the return address runs the body), so the result is the instruction after the call. While a step-over runs you'll see the usual bp.hit → debugger.entered → state.paused events for its internal temporary breakpoint; the reply still arrives synchronously.

⚠️

bad_state — CPU not paused. busy — a previous cpu.step_over is still resuming to its temporary BP; wait, or cpu.pause to bail (the pause delivers the pending reply). If the stepped call never returns, recover with cpu.pause.

09 Breakpoints #

bp.add / bp.list / bp.del #

bp.hitstable handle
★
Ability: typed execution & interrupt breakpoints — the same CPU-halting kind the debugger uses — addressed by a stable bp_id handle assigned at creation, so a handle stays valid as other breakpoints come and go. The typed replacement for BP CS:IP / BPINT / BPDEL strings.
// execution breakpoint at SEG:OFF (kind defaults to "exec")
{"id": 1, "cmd": "bp.add", "args": {"addr": "0824:6F8E"}}
  → {"bp_id": 7, "kind": "exec", "addr": "0824:6F8E", "seg": 2084, "off": 28558}

// interrupt breakpoint: INT 21h, optionally narrowed to AH (and AL)
{"id": 2, "cmd": "bp.add", "args": {"kind": "int", "int": 33, "ah": 9}}
  → {"bp_id": 8, "kind": "int", "int": 33, "ah": 9}

{"id": 3, "cmd": "bp.list"}
  → {"count": 2, "breakpoints": [
       {"bp_id": 8, "index": 0, "kind": "int", "enabled": true, "hits": 0, "int": 33},
       {"bp_id": 7, "index": 1, "kind": "exec", "enabled": true, "hits": 0,
        "addr": "0824:6F8E", "seg": 2084, "off": 28558, "bytes_now": "8B 46 FE 50"}]}

{"id": 4, "cmd": "bp.del", "args": {"bp_id": 7}}
  → {"deleted": 1, "bp_id": 7, "remaining": 1}     // not_found if the id is gone
{"id": 5, "cmd": "bp.del", "args": {"all": true}}   // remove EVERY breakpoint
  → {"deleted": 1, "remaining": 0}
  • bp.add — {"addr":"SEG:OFF"} for an exec BP; {"kind":"int","int":N} for an interrupt BP, optionally narrowed with ah and al (al requires ah). Added BPs activate immediately — no pause/run cycle.
  • bp.list — every real BP with its bp_id, the (shifting) iteration index, kind, enabled, hits, and address (plus bytes_now — the 4 live bytes at the address, catching a stale/relocated BP for free).
  • bp.del — {"bp_id":N} removes one; {"all":true} removes every BP (must be explicit so an omitted id never wipes the list).
ℹ️

bp_id is stable; bp_index is not. The bp.hit event carries both — correlate on bp_id, because bp_index shifts on every add/del.

bp.set / bp.clear #

heavy-debugbp.cond
★
Ability: conditional / Nth-hit breakpoints with an atomic on-hit capture macro — snapshot registers / traceback / memory at the trigger instant, before the emulator advances. Removes the timing skew between "halt" and "capture" and the manual break/inspect/resume race entirely.
{"id": 1, "cmd": "bp.set", "args": {
   "addr": "0824:6F8E",
   "if": "sp==0x0200",
   "do": [{"cmd": "regs.get"}, {"cmd": "cpu.traceback", "args": {"count": 64}}],
   "continue": false}}
  → {"bp_id": 1, "addr": "0824:6F8E", "seg": 2084, "off": 28558,
     "condition": "sp==0x0200", "macro_len": 2, "continue": false}

When reached and the condition holds, it emits a bp.cond event carrying the macro output, then (unless continue is true) halts:

{"event": "bp.cond", "bp_id": 1, "addr": "0824:6F8E", "seg": 2084, "off": 28558,
 "hits": 7, "halted": true, "from": "0824:6F10", "from_cs": 2084, "from_ip": 28432,
 "results": [{"cmd": "regs.get", "ok": true, "result": {…}},
             {"cmd": "cpu.traceback", "ok": true, "result": {"entries": […]}}]}
  • if (optional) — a single comparison operand [& mask] op operand. Ops: == != < <= > >= (unsigned). Operands: a register, the literal hits (this BP's own reach count, for "hits==7"), a number, or a memory reference [byte|word|dword] [ [seg:] off [±disp] ] (word default, segment defaults to DS — so [si+04] is [ds:si+04]). Omitted → always fires.
  • do (optional) — read-only macro commands run when the condition holds. Allowed: regs.get, mem.read, cpu.disasm, cpu.traceback, debug.status.
  • continue (default false) — true runs the macro then auto-resumes (a non-halting probe that still reports each fire).

debug.status reports every conditional BP under cond_breakpoints with hits (reached) and fires (condition held) — so "reached but never matched" is distinguishable from "matched N times" without consuming the stream. bp.clear removes them: {"bp_id":N} for one, no args for all.

⚠️

Conditions read memory as physical real-mode bytes ((seg<<4)+off) — no page translation. The per-instruction condition check needs C_HEAVY_DEBUG; a non-heavy build replies unsupported. Limits: 32 BPs / 16 macro commands.

debugger.command #

text in, text out
★
Ability: pass any text the curses debugger accepts and read back whatever DEBUG_ShowMsg produces — the escape hatch for everything without a typed command yet.

Use it for interrupt inspection (INT), descriptor tables (IDT, GDT), DOS internals (DOS MCBS/DEVS/XMS/EMS, BIOS MEM, CALLBACKS, KERN), and the EV expression evaluator. output is the captured text (empty for commands that don't emit through DEBUG_ShowMsg); recognized is ParseCommand's return — trust output over this flag, many recognised commands still return false.

⚠️

Don't use it for register dumps (no R command exists — use regs.get) or memory dumps (MEMDUMP writes a file — use mem.read). Output formatting can change between versions; don't build brittle parsers on it.

10 Keyboard #

keyboard.type #

ASCII only
★
Ability: push ASCII text into the guest's paste buffer — the easy way to drive a DOS prompt or app. \r presses Enter (\n works on most DOS apps too).

The existing paste pump delivers one character per [sdl] pastespeed tick (default 30 ms). The reply's queued is the byte count appended (not characters typed yet) — there's no built-in "wait until drained", so sleep len(text) * pastespeed_ms if you must be sure DOS has seen it before sending more. Non-ASCII bytes produce undefined scancodes.

keyboard.press / .release / .tap #

raw make/break
★
Ability: raw key make/break events by name — for modifier combos and special keys the paste path can't express. tap is press-then-release.
# Held modifiers (e.g. Ctrl+C) are explicit press/release pairs:
a.keyboard_press("leftctrl")
a.keyboard_tap("c")
a.keyboard_release("leftctrl")

11 Transfer watches #

Three siblings answering "who jumped/called/returned here?" — the canonical answer when the CPU lands at an unexpected CS:IP. Each is a cheap per-transfer compare you can leave armed across long runs.

farcall.watch / .unwatch #

farcall.transfer
★
Ability: catch every FAR transfer (CALL FAR, JMP FAR, RETF, IRET, interrupt dispatch) whose destination CS equals a sentinel segment, and learn which instruction did it.

Set target_seg (a u16 decimal or hex string), or a set with target_segs: [...] (the array form replaces the whole set; [] clears). Each event carries a which index into the set.

{"event": "farcall.transfer",
 "target_seg": 18492, "target_off": 4068,
 "from_cs": 2084, "from_ip": 24576,
 "kind": "call_far_direct", "which": 0}

kind is one of call_far_direct, call_far_indirect, jmp_far_direct, jmp_far_indirect, retf, iret, or an interrupt-source label (int3, int_sw, into, int_hw, int_exception, int_step_trap, int_nmi, int_icebp). For RETF the target is read from the stack frame it pops — the authoritative "who's about to return here?".

cpu.watch_target / .unwatch_target #

cpu.transfer
★
Ability: the NEAR-transfer sibling. When you know the exact (CS, IP) the CPU lands at, find the NEAR instruction that jumped/called/returned there. Covers every direct/indirect NEAR transfer plus taken Jcc/LOOP/JCXZ and RETN.

Because NEAR transfers are common, the sentinel is a (seg, off) pair — only the exact destination fires. Set target_seg+target_off, or a set with targets: ["SEG:OFF", …].

{"event": "cpu.transfer",
 "target_seg": 2084, "target_off": 59598,
 "from_cs": 2084, "from_ip": 8512,
 "kind": "jmp_near_indirect", "which": 0}
kindOpcode group
call_near_direct0xE8 (rel16, plus rel32 under 0x66)
jmp_near_direct0xE9 (rel16/rel32)
jmp_short0xEB (rel8)
call_near_indirect0xFF /2
jmp_near_indirect0xFF /4
retn / retn_imm0xC3 / 0xC2 imm16
jcc_short0x70..0x7F taken — also LOOP/JCXZ
jcc_near0x0F 0x80..0x8F taken (386+)
retf / iret0xCA/CB / 0xCF (popped CS = current CS)
int3…int_icebpsoftware / hardware / exception / NMI / ICEBP dispatch
callback_far / _intC++-side CALLBACK_RunRealFar[Int] dispatch
hbp_execheavy-debug fallback: reached via a transfer no hook caught

Conditional jumps emit only when taken. For opcode-driven NEAR kinds from_cs == target_seg (a NEAR transfer can't change CS); for int_*/retf/iret the target CS can differ. from_ip is the post-operand IP (the return address), so disassembling backwards from it finds the source.

cpu.watch_range / .unwatch_range #

cpu.range_enter
★
Ability: the boundary-crossing sibling. Fires when the CPU transfers into [seg, lo..hi] from outside that window — and crucially not on intra-range transfers (the slide, internal loops, intra-range Jccs). The "from outside" gate reports just the single entry instruction, not the long slide that follows.

Set seg+lo+hi (lo <= hi), or a set with ranges: [{seg, lo, hi}, …]. Each window keeps its own gate and hit counter.

{"event": "cpu.range_enter",
 "seg": 2084, "target_off": 39274,
 "from_cs": 2084, "from_ip": 50071,
 "kind": "jmp_near_indirect", "which": 0}
💡

Typical use: find which instruction diverts execution into a script-data table the CPU is fall-through-executing as code. Arm the range over the table, run the repro, take the first cpu.range_enter — its from_cs:from_ip is the divert source. A FAR transfer landing in seg from a different source segment trivially satisfies the gate.

Interrupt-sourced transfers

Both cpu.watch_target and farcall.watch also fire on every interrupt dispatch — INT 3/INT N/INTO/ICEBP, PIC-injected hardware interrupts, CPU exceptions, the TF=1 single-step trap, and NMI. So farcall.watch target_seg=<game_cs> shows every timer ISR dispatch (one kind="int_hw" per ~55 ms) plus every INT 21h/INT 10h whose IVT entry points into that segment. callback_far/callback_far_int fire when DOSBox-X's C++ synthetically sets CS:IP to invoke a guest routine without an opcode (DOS device strategy/interrupt entry, XMS callbacks, INT 16 wrap, shell exec).

12 Observability & trust #

🔬

These commands answer the question that otherwise forks every silent watch/breakpoint result into two un-decidable hypotheses: did the CPU never reach that address (real behaviour), or did the debugger fail to observe it (tool deficiency)? Every armed observer is independently provable — you never take the debugger's silence on faith.

debug.status #

non-haltingrunning or paused
★
Ability: one typed snapshot of everything — CPU state, instruction count, every breakpoint and watch with its authoritative hit counter — readable while running, without consuming the event stream.

  "breakpoints": [

                             {"seg": 4096, "off": 64, "hits": 2}]},
    "range":  {"armed": true, "hits": 7, "seg": 2084, "lo": 38400, "hi": 39423, …},
    "mem":    {"armed": true, "hits": 3, "seg": 2084, "lo": 24576, "hi": 28671,

💡

The canonical use (the "C01E saga"): arm a BP, a cpu.watch_target, and a cpu.probe on one address; drive the repro; read debug.status. If the BP and probe hits agree but the watch hits is 0, the watch path is provably the bug — settled in one run. bytes_now (the live 4 bytes at each exec BP) catches "armed on a wrong/relocated address" for free.

cpu.probe #

heavy-debugnever halts
★
Ability: a non-halting execution counter — a set of SEG:OFF points, each with its own counter, checked once per instruction. It never halts and emits no event, so it runs at full speed and sidesteps the ~20× halting-BP slowdown that often starves a repro before it reaches the bug window.
{"id": 1, "cmd": "cpu.probe", "args": {"points": ["0824:6F10", "0824:99E2"]}}  → {"armed": 2}
{"id": 2, "cmd": "cpu.probe", "args": {"points": []}}                          → {"armed": 0}

Counts read back via debug.status's probe array. Up to 256 points; calling again replaces the set. After a full-speed run: hits == 0 ⇒ provably never executed; hits > 0 ⇒ provably on the path.

cpu.trace_ring / .traceback #

heavy-debug
★
Ability: "how did the CPU get here?" — a fixed-size ring recording the retired (seg, off) of every executed instruction, dumped backward and disassembled. Reconstructs an entire backward slide in one capture instead of an O(N)-run byte-walk, with no data-as-code alignment guessing.
{"id": 1, "cmd": "cpu.trace_ring", "args": {"depth": 256, "seg": "0824"}}
   → {"enabled": true, "depth": 256, "seg": 2084}
// ... drive to a breakpoint/pause ...
{"id": 2, "cmd": "cpu.traceback", "args": {"count": 64}}
   → {"entries": [
        {"cs_ip": "0824:9849", "bytes": "00 00", "text": "add [bx+si],al"},
        {"cs_ip": "0824:99E2", "bytes": "63 C0", "text": "arpl ax,ax"}   // most-recent last
     ]}

Consecutive duplicates of the same CS:IP collapse to one (so a halting BP can't flood the ring). Optional seg filters to one code segment. enabled:false stops recording but retains the ring, so a traceback after the CPU pauses still works. depth defaults to 256, capped at 4096.

cpu.disasm #

structured
★
Ability: structured disassembly — count instructions from SEG:OFF, reusing the same DasmI386 the curses debugger uses. Removes the unsafe hand-decode of raw bytes.
{"id": 1, "cmd": "cpu.disasm", "args": {"addr": "0824:99C5", "count": 4}}
   → {"insns": [{"cs_ip": "0824:99C5", "bytes": "E2 41", "text": "loop 0x9A08"}, …]}

bytes is the exact raw encoding (always agrees with mem.read of the same address); text is the decoded mnemonic. Default count 1, max 64. Operand size follows the current code segment (cpu.code.big).

13 State snapshots #

state.save / .restore #

paused onlyheadless
★
Ability: snapshot the whole machine once you've driven the guest to the interesting point, then restore to it instantly, as many times as you like — instead of re-driving (boot, mount, launch, navigate) every iteration. This is what makes an investigate-fix-retry loop fast and deterministic: every restore lands on byte-identical state.
{"id": 1, "cmd": "state.save", "args": {"slot": 7}}
  → {"slot": 7, "name": "[Program: OBSTEST] (2026-06-01 14:02)"}

{"id": 2, "cmd": "state.restore", "args": {"slot": 7}}
  → {"slot": 7, "name": "…",
     "regs": {"eax": 43690, … , "eflags": 518},
     "cs_ip": "0814:0000017D",
     "insn": {"cs_ip": "0814:017D", "bytes": "B8 AA AA", "text": "mov ax,0xaaaa"}}
  • slot — an integer in [0,99], the same slots the Capture → Save/Load state menu uses (pick a high slot to avoid clobbering a hand-saved state). state.restore returns the restored CPU as {regs, cs_ip, insn} — the cpu.step shape.
  • Headless: the interactive remark prompt and the version/program/memory/machine-type confirmation dialogs are suppressed; slot is always honoured regardless of any savefile= config.
  • Breakpoints, the trace ring, cpu.probe points and mem.watch are agent/debugger constructs and are not part of the snapshot — they survive a restore unchanged. Only guest state (CPU, memory, devices) is saved.

state.restore followed by cpu.run is fully supported (restore, resume, run, then arm a conditional BP). Errors: bad_state (not paused), bad_args (slot out of range), not_found (empty slot), unsupported (> 1 GB guest memory), io_error (slot file unwritable).

14 Screen capture #

screen.capture #

deferred replyscreen.captured
★
Ability: trigger DOSBox-X's existing screenshot path and get back the absolute path of the written PNG — the same encoder the Host+P hotkeys drive, so the pixels are identical.
  • raw (default true) — true writes the raw VGA scan-line capture (native resolution, true palette, no scaler, .raw1.png); false writes the cooked render-output capture (post-scaler, .png). Default raw keeps pixel offsets honest for RE / shift analysis.
  • The [dosbox] captures= setting must be non-empty (else bad_state). Files auto-number under that directory.
⚠️

The reply is deferred and the CPU must be running — the render path doesn't fire while paused. The encoder runs on the next VGA frame; once written, the agent sends both the reply for your id ({"path","raw"}) and a screen.captured event. The reference client's call() blocks transparently (~30 ms round-trip).

⛔

raw=true requires an animating screen. The raw VGA capture is driven by VGA_DrawRawLine, which only fires while the VGA emulator is actively drawing scanlines. On a static screen the on-demand renderer skips unchanged frames, so raw waits forever — the agent enforces a 2-second deadline then returns timeout. For static screens use raw=false (the cooked path runs every frame).

res = a.call("screen.capture")               # raw=True by default
img_path = pathlib.Path(res["path"])          # absolute path on disk
data = img_path.read_bytes()                   # PNG bytes

Other errors: bad_args (non-bool raw), busy (another capture pending).

18 What is not capturable #

The Phase-1 surface covers what ParseCommand routes through DEBUG_ShowMsg plus the structured queries. Several things the curses debugger does cannot be reached through the agent:

  • Curses pane content. The register pane, disassembly window, hex/ASCII data view, variables pane and FPU stack pane all draw directly to ncurses windows — they never go through DEBUG_ShowMsg, so they produce empty output. Use regs.get / mem.read, and for disassembly cpu.disasm.
  • Pane-setter commands. D, DV, DP, C, SHOWWIN/HIDEWIN, MOVEWINDN/MOVEWINUP only mutate which curses window shows what — they reply with a short status string, never the hex dump.
  • File-output commands. MEMDUMP/MEMDUMPBIN write files in DOSBox-X's cwd; LOG/LOGS/LOGL/LOGC write CPU trace logs to disk. The agent sees only a one-line "success". Use mem.read for byte access.
  • Single-stepping with structured output via T/P. Those refresh curses panes — but you don't need them: cpu.step / cpu.step_over return the post-step registers, CS:IP and disassembly directly.
  • The R register-dump command. It doesn't exist in ParseCommand (the curses key R is a UI handler). Use regs.get.
  • Mouse input — planned for Phase 2. Phase 2

Pages of scrollable content (long BPLIST/IDT/GDT listings) are fully captured — paging is a curses display concept and DEBUG_ShowMsg writes each line. If you discover something else that emits to a pane rather than DEBUG_ShowMsg, that's a candidate for a Phase-2 typed command — file an issue.

19 Recipes #

Set a code breakpoint, run, wait for it, inspect state

import base64

a.debugger_command("BP CS:0100")        # breakpoint at current CS:0100
a.cpu_run()
while True:
    ev = a.next_event(timeout=10.0)
    if ev is None: raise TimeoutError("breakpoint never hit")
    if ev.get("event") == "bp.hit":
        print(f"hit bp {ev['bp_index']} at {ev['seg']:04x}:{ev['off']:08x}")
        break
# CPU is now paused. Inspect with the typed snapshot commands.
regs = a.call("regs.get")
print(f"EAX={regs['eax']:08x} CS:EIP={regs['cs']:04x}:{regs['eip']:08x}")
mem = a.call("mem.read", kind="seg:off",
             addr=f"{regs['ds']:04x}:{regs['esi']:04x}", len=32)
print(base64.b64decode(mem["bytes"]).hex())
a.cpu_run()                              # resume

Break on every PIT timer tick (handy smoke test)

a.debugger_command("BPINT 08")
a.cpu_run()
ev = a.next_event(timeout=2.0)            # arrives ~55 ms after RUN
💡

Prefer BPINT 08 over BPINT 21 for testing — the PIT fires ~18×/sec regardless of guest state. INT 21h is only issued by code that asks; an idle COMMAND.COM prompt is blocked on INT 16h and will never trip a bare BPINT 21.

Find the caller of a far transfer to a known segment

a.call("farcall.watch", target_seg="483C")    # or 0x483C, or 18492
a.keyboard_tap("space")                       # trigger whatever reproduces
while True:
    ev = a.next_event(timeout=10.0)
    if ev is None: raise TimeoutError("no far-transfer to 483C in 10s")
    if ev.get("event") == "farcall.transfer":
        print(f"{ev['kind']} from {ev['from_cs']:04x}:{ev['from_ip']:04x} "
              f"-> {ev['target_seg']:04x}:{ev['target_off']:04x}")
        break
a.call("farcall.unwatch")
# now snapshot regs/stack and dig

The first matching event names the source of the bad far transfer — the instruction to start working backwards from.

Stream all log output

a.log_subscribe()
for ev in a.events(timeout=None):         # block forever
    if ev.get("event") == "log.line":
        print(ev["text"])

Run a DOS command and wait for the prompt

a.keyboard_type("DIR\r")
# pastespeed default = 30 ms/char, so worst case ~0.12 s for "DIR\r"
time.sleep(0.5)

There is no "wait for prompt" primitive in Phase 1. If you need synchronization, set a breakpoint on INT 21 / AH=08 (keyboard input with echo) or just sleep generously.

20 Gotchas #

  • Wait for the portfile. The listener starts during DOS init, not at process spawn. Poll for the file's existence before connecting. It's written atomically (write+rename), so once it appears you get a complete port number — no retry on empty reads.
  • Bind shows as 0.0.0.0 in netstat. SDL_net's bind API can only bind INADDR_ANY; loopback enforcement happens per-accept by inspecting the peer. Non-loopback peers are dropped immediately. Windows may show a firewall prompt the first time; only Private permission is needed.
  • One client at a time. A second connection gets {"event":"busy"} and is closed. Don't multiplex multiple drivers.
  • Curses is disabled when the agent runs. With -agent-listen active, Alt-Pause / Alt-F12 no longer opens a curses window — the agent owns the debugger UI. Boot without -agent-* flags to use curses interactively.
  • debugger.command is text in, text out. Formatting can change between versions; don't write brittle parsers. Use the typed regs.* / mem.* commands instead.
  • keyboard.type is ASCII only. Non-ASCII is silently mangled by the paste driver — use press/release/tap with named keys for non-ASCII or modifier combos.
  • bp_index is not stable; bp_id is. Deleting a breakpoint shifts all later indices down. Use the typed bp.add/bp.list/bp.del handle. bp.hit carries both — correlate on bp_id.
  • BPs added via debugger.command activate immediately. Setting BP/BPM/BPINT while running takes effect on the very next fetch — the old pause-set-resume workaround is no longer required.
  • agent.overflow means lines were dropped. Outbox cap is 1 MB per client. Drain events() more aggressively, or unsubscribe from log.line if you don't need it.
  • Release builds have no agent at all. No listener, no port file, no CLI flags accepted. You need a Debug build.

21 Reference client #

contrib/agent-client/dbxagent.py (stdlib only). Sync call(cmd, **args) plus typed helpers (vm_version, cpu_pause, cpu_run, regs_get, mem_read, keyboard_type, keyboard_tap, keyboard_press, keyboard_release, debugger_command, log_subscribe, log_unsubscribe). mem_read decodes the base64 for you and returns raw bytes. Events arrive via next_event(timeout) / events(timeout). The reader is a daemon thread; closing the socket unblocks it; use it as a context manager.

    --type "DIR\r" --cmd BPLIST --events 5

Read the file — it doubles as a worked example for writing a client in another language.
